# OMS v0.1 验证记录

日期：2026-10-14。本轮范围为本机独立进程、持久化 OMS、策略接入与协议验证，不包含真实券商执行。

## 自动验证

阶段测试覆盖订单 Decimal / 结构约束、重复命令、迟到批准、会话失效、数据库事务回滚／独占写锁、成交乱序／重复／更正、两腿累计、手续费版本、撤成竞争、NATS 实际权限、策略独立流、断连恢复要求、策略本地手续费去重和健康状态过期。

在专用 PostgreSQL 测试库与临时文件型 JetStream 上执行；未修改用户的行情数据库或 OpenD 配置。最终数量及评审修复见下方最终验证部分。

## 原生独立进程联调

同时运行 NATS、OMS、行情网关、两策略，以及分别独立的临时 Risk／Execution 模拟进程。进程使用安装的 wheel，不依靠跨仓库 PYTHONPATH。

- alpha：两笔股票委托，一笔撤成，一笔修改限价后成交；收到订单／成交／费用回调。
- beta：一笔 bull put 两腿信用价差，两腿分别成交和更新费用；同一逻辑订单完成。
- 共 3 个逻辑订单、5 个执行命令（3 新单、1 撤单、1 改单），最终为 CANCELLED、FILLED、FILLED。
- 重启 OMS 与两个策略后，feed_epoch 保持不变，快照分别恢复 2 / 1 个订单，执行命令仍为 5 个，无重复产生订单。
- 同时连接本机 `127.0.0.1:11111` Futu OpenD。订阅建立、一次性查询返回 `PARTIAL / STALE_DATA`；没有新鲜 QUOTE 回调，不据此声称新鲜实时行情决策已通过。

模拟期权合约仅用于验证订单状态机，不代表已通过券商合约资格核验。所有执行发生在 SIMULATION 域，无真实订单。

## 交付边界

真实 Risk、Execution／ib_async、券商对账、资金／持仓账本、到期／行权／指派、Linux Docker、压力与跨交易日长测仍未实现。快照和消息容量限制见 [接口](interfaces.md)；需要在规模扩大前完成归档／分页能力。

沿用项目所有者的清理要求：测试源码、临时模拟进程及临时策略在最终验证后删除；交付目录保留服务、SDK、模板接入、配置和文档。本地验证记录可恢复，GitHub 本轮未发布。

## 最终验证与独立评审

最终新增／集成检查 **26 项通过**。另外从本地历史恢复了既有策略回归检查，在临时目录运行：**32 项通过**；排除两条已过时用例（旧版 OMS 禁用要求和已按要求删除的示例策略），新的 paper/live 模式检查已覆盖替代要求。

独立评审提出两项问题，均以真实 JetStream 失败用例复现并修复：

1. 接收成交后、数据库提交前崩溃：OMS 入口改为逐条确认；恢复后先补原成交，再处理费用／更正。验证原成交与费用均保留且无隔离记录。
2. 压力下新单反复 NAK 阻塞撤单：改为持久化 OMS_BUSY 拒绝并 ACK。验证积压超过阈值、连续 35 个新单之后的撤单仍被及时处理。

最终安装包重新通过独立进程联调和 OMS／策略重启检查。另在临时干净目录复制交付文件，以 `--locked` 安装 OMS 和策略框架；模板生成、独立 wheel 安装、entry point 发现及配置校验通过。策略环境不含 OMS 服务、Futu、IB、PostgreSQL 驱动或 pytest；订单类型为同一个 oms_protocol 类。OMS wheel 包含数据库 SQL，服务 CLI 可用。

实现取舍保持不变：先模拟执行域、改单先限价格、快照容量超限明确拒绝、订单断连通过重启回放恢复。对应代价是实际 Risk／Execution 验证、扩大规模前的分页／归档，以及监督进程的重启／租约退避需要后续实施。真实券商 fencing／对账、风险政策和持仓、Docker／主机高可用、自动解冻均属后续模块；测试源码清理是项目所有者要求，新鲜行情尚未验收，不能扩张本次通过结论。
