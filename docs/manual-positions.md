# 手工持仓共存与内部成交对账

适用版本：account-service 0.3.0、Execution 0.4.0、Portfolio SDK 0.3.0。订单协议保持 0.4.0；策略 Runtime 更新到 0.6.2 以固定新的 SDK 依赖。账户服务、Execution 与策略环境须协调更新，不混用旧快照解析器。

## 归属

用户可以继续手工交易。策略的数量、成本、损益、开仓批次只从本系统经 OMS 记录的成交生成；券商净持仓不会自动分配给任何策略。多个策略或手工交易同一个合约时，IB 总持仓可以相互抵消，不能据此覆盖内部策略账本。

`external_positions.unassigned_quantity = broker_quantity - strategy_quantity`。此差额持续随券商快照变化，无须逐次登记固定基线；QQQ、同合约手工增减或反向净持仓均不会仅因差额阻塞系统。差额表示外部／未分配，并不能证明其来源一定是人工交易；行权、指派、公司行动等仍不属于本版处理范围。

策略平仓仍必须引用自己的真实开仓 `position_id`，由 Risk 原子核验剩余数量及其他未成交平仓预占。外部持仓没有策略批次，不能用于策略平仓。手工操作自动化所用的同一标的时，系统继续保留策略的虚拟归属；如希望人工减仓同时减少策略批次，需要后续显式归属调整能力，本版不会猜测或自动改账。

## 对账依据

Execution 从自己的持久逐腿成交、原始订单身份及开仓／平仓方向汇总 `managed_positions`，与新鲜券商持仓一起发送。该投影不读取 OMS 或 Portfolio 数据库。按历史 instrument_id／版本／conId 汇总后，只要求非零余额仍能映射到当前受控合约目录；已归零旧合约可移出活跃交易目录，不跨身份抵消。

Portfolio 将 OMS 成交得到的策略数量合计与 Execution 的自有成交投影比较。少记、多记或身份不匹配会得到 `MANAGED_POSITION_MISMATCH`／`UNMAPPED` 并阻止审批，不会把内部账本差异直接当成手工持仓。匹配后才允许把券商与内部数量差额作为外部持仓列示。

快照仍须满足：同账户／模式／feed_epoch、券商完整且稳定、新鲜、Portfolio 追平 OMS、经济账本版本在采集期间不变。Execution 启动恢复未完成、断线、冻结、报告 outbox 未发送、回报仍在队列或已经取出但尚未落库、成交／取消累计量待证明时，不发布稳定证明。多接口采集不是全局原子事务；新的手工操作反映到下一次成功快照。

`POSITIONS_MATCHED` 在新版表示系统自有成交数量交叉核对成功，允许存在外部差额；不表示账户没有外部风险，也不表示券商总持仓等于某个策略持仓。旧生产者没有 `managed_positions` 时继续采用原始严格总量核对，有外部差额即不就绪。`null` 与显式空列表不可混为一谈。

## 风控与费用

账户级和策略级 Risk 额度覆盖本系统管理的订单及持仓；外部资产不计入策略额度，不凭未分配数量调整审批预算。IB 的资金、保证金与购买力仍是同一账户共享，手工交易可影响券商是否接受订单，不能承诺经济上完全隔离。本版未实现完整账户保证金模型或外部持仓风险估值。

实际手续费超过已审批缓冲时，保留 `FEE_BUFFER_EXCEEDED` 并拒绝新增风险。若该费用冻结由本版本在此前无结构错误时产生，会持久记录 `fee_close_allowed`；仅有此来源证明的费用冻结允许继续核验自有持仓平仓。所有归属、数量、Portfolio、水位、结构一致性、OMS 阻断及订单限制仍执行。费用事件不能覆盖已有结构性冻结，旧库费用冻结没有该标记时保守拒绝，不自动解除。

修改费用配置不会重写历史预占或清除既有冻结。模拟示例的每单位每腿费用缓冲改为 2 美元，是测试配置，不是费率保证；实际费率、交易单位和拆单情况需要匹配部署账户。费用冻结的人工核对／解除工具不在本轮范围，禁止删除生产数据库或手工伪造标记绕过。
